# Employee Task Tracker

## Описание проекта

**Employee Task Tracker** — это REST API-система управления сотрудниками и задачами, разработанная на Django REST Framework.

Проект предназначен для руководителей и позволяет вести учет сотрудников, создавать и контролировать задачи, распределять работу между исполнителями, анализировать загрузку сотрудников и находить оптимальных исполнителей для новых задач.

Основная идея проекта — автоматизация управления рабочими процессами внутри команды с учетом текущей загрузки сотрудников и их доступности.

---

## Цель проекта

Создать сервис управления задачами сотрудников, который позволяет:

- вести учет сотрудников организации;
- создавать и контролировать задачи;
- назначать исполнителей;
- учитывать статус сотрудников;
- контролировать сроки выполнения задач;
- анализировать загрузку сотрудников;
- автоматически находить подходящих исполнителей;
- обеспечивать изоляцию данных между пользователями.

Каждый пользователь работает только со своей командой сотрудников и своими задачами.

### Технологический стек
 - Язык разработки: Python 3.12+Фреймворк: Django 6.0 / Django REST Framework (DRF)
 - База данных: PostgreSQL
 - Авторизация: JWT-токены (rest_framework_simplejwt)
 - Документация: Swagger / ReDoc (drf-yasg)
 - Тестирование и метрики: Django Testing Framework + coverage

### Права доступа и Пагинация

1. Доступ к эндпоинтам: Все эндпоинты управления сотрудниками и задачами требуют обязательной JWT-авторизации *(IsAuthenticated)*.
2. Владение объектами: Изменение *(update)*, частичное изменение *(partial_update)*, удаление *(delete)* и детальный просмотр *(retrieve)* сотрудников и задач доступны исключительно их создателю *(owner = request.user)*. При создании новой сотрудника и задачи владелец *(owner)* проставляется автоматически на основе текущей сессии пользователя *(owner = request.user)*.
3. Пагинация: Для всех списков сотрудников и задач используется пагинация *(REST_FRAMEWORK: DEFAULT_PAGINATION_CLASS)*.
4. Реализована автоматическая привязка сотрудника к владельцу:
```owner = request.user```
5. Пользователь не может создать или изменить сотрудника другого пользователя.

### Полный список эндпоинтов API

1. Управление пользователями и авторизация (users/)

| Метод         | URL-путь                | Описание эндпоинта                                    | Доступ                      |
|:--------------|:------------------------|:------------------------------------------------------|:----------------------------|
| **POST**      | `/users/register/`      | Регистрация нового пользователя                       | Доступно всем (`AllowAny`)  |
| **POST**      | `/users/login/`         | Получение JWT-токенов                                 | Доступно всем (`AllowAny`)  |
| **POST**      | `/users/token/refresh/` | Обновление истекшего access токена                    | Доступно всем (AllowAny)    |
| **GET**       | `/users/users/<id>/`    | Детальный просмотр своего профиля                     | Авторизованные пользователи |
| **PUT/PATCH** | `/users/users/<id>/`    | Полное или частичное редактирование своего профиля    | Только владелец             |
| **DELETE**    | `/users/users/<id>/`    | Удаление профиля пользователя                         | Только владелец             |

2. Управление сотрудниками (api/employees/)

| Метод           | URL-путь                  | Описание эндпоинта                             | Доступ            |
|:----------------|:--------------------------|:-----------------------------------------------|:------------------|
| **GET**         | `/employees/`             | Список сотрудников текущего пользователя       | Только владелец   |
| **POST**        | `/employees/create/`      | Создание нового сотрудника                     | Только владелец   |
| **GET**         | `/employees/<id>/`        | Детальный просмотр данных сотрудника           | Только владелец   |
| **PUT/PATCH**   | `/employees/<id>/update/` | Полное или частичное редактирование сотрудника | Только владелец   |
| **DELETE**      | `/employees/<id>/delete/` | Безвозвратное удаление сотрудника из системы   | Только владелец   |

3. Управление задачами (api/tasks/)

| Метод         | URL-путь              | Описание эндпоинта                         | Доступ            |
|:--------------|:----------------------|:-------------------------------------------|:------------------|
| **GET**       | `/tasks/`             | Список задач текущего пользователя         | Только владелец   |
| **POST**      | `/tasks/create/`      | Создание новой задачи                      | Только владелец   |
| **GET**       | `/tasks/<id>/`        | Детальный просмотр конкретной задачи       | Только владелец   |

| Метод    | URL-путь                    | Описание эндпоинта                             | Доступ            |

### Регистрация пользователя

- авторизация выполняется через Email вместо username;
- поддерживается JWT-аутентификация;
- реализовано подтверждение электронной почты;
- пользователь может просматривать и изменять только собственный профиль;
- администратор имеет доступ ко всем пользователям.

При регистрации:

1. создается пользователь;
2. аккаунт получает статус неактивного;
3. генерируется уникальный токен подтверждения;
4. пользователю отправляется письмо со ссылкой активации.

После перехода по ссылке аккаунт становится активным.

---

При назначении задачи выполняются проверки:

- исполнитель принадлежит текущему пользователю;
- сотрудник находится на работе;
- нельзя назначить задачу сотруднику в отпуске, на больничном или выходном.

Также проверяется срок выполнения задачи:

- нельзя установить дату выполнения раньше текущего времени.

---

5. `api/employees/?task_id=`

При передаче параметра `task_id` (id конкретной задачи) выполняется подбор сотрудников для ее выполнения.

Алгоритм учитывает:

- текущую загрузку сотрудников;
- статус сотрудника;
- наличие родительской задачи.

Правила:

1. В первую очередь выбираются сотрудники с минимальным количеством активных задач.

2. Если у задачи есть родительская задача:
   - рассматривается исполнитель родительской задачи;
   - он может быть выбран, если его загрузка отличается не более чем на 2 активные задачи от минимальной.

В ответе отображается причина выбора:

- "Минимальная загрузка";
- "Исполнитель родительской задачи".

# Возможности сотрудников

Каждый сотрудник имеет:
- ФИО;
- должность;
- Email;
- телефон;
- статус.

Доступные статусы:
- На работе;
- Отпуск;
- Больничный;
- Выходной.

ФИО формируется автоматически из отдельных полей:
- фамилия;
- имя;
- отчество.

---

# Статусы задач

Задача может иметь состояние:
- Создана;
- Выполняется;
- Завершена.

При завершении задачи автоматически устанавливается дата завершения.
Если задача возвращается в другой статус — дата завершения очищается.
При назначении задаче исполнителя статус автоматически устанавливается "Выполняется"

# Фильтрация и сортировка

Поддерживается фильтрация:

## Сотрудники

По:
- фамилии;
- статусу;
- должности.

## Задачи

По:
- статусу;
- исполнителю;
- родительской задаче.

Сортировка задач:
- по id;
- по сроку выполнения;
- по приоритету.

Для обратной сортировки используется:
```-ordering_field```

Пример:
```
/api/tasks/?ordering=-deadline
```
